# АТЛАС СВЕТА R14.2 — проверка VK Mini Apps / Одноклассников и производительности

Дата: 12 октября 2026 года. Основа: `ATLAS_LIGHT_R14_1_VK_MINI_APPS_AUDITED.zip`.

## Вердикт

Технические исправления внесены, но **абсолютное соответствие всей актуальной редакции VK Mini Apps Rules не подтверждено**. По адресу https://dev.vk.com/ru/mini-apps-rules страницы не удалось получить полный текст в ходе нескольких обращений. Для ОК использована доступная официальная документация (ссылки ниже), в том числе таблица совместимости VK Bridge. Реальных тестов в официальных клиентах VK/OK, в кабинете разработчика и действительных рекламных показов не проводилось.

**Не следует отправлять игру на модерацию, полагаясь только на этот отчёт:** сначала проверить условия из кабинета разработчика и реальную интеграцию для обеих платформ.

## Найденное и исправленное

1. **Определение ОК-клиента:** `vk_client=ok`. Сборка использует общий VK Bridge, но отдельно учитывает исключения по совместимости ОК. Старая схема FAPI не добавляется: для нового VK Mini App это не требуется.
2. **Неподдерживаемый Bridge:** для ОК больше не вызывается `VKWebAppSetSwipeSettings`. В VK управление свайпом остаётся прежним; внутренние переходы на History API сохранены в обеих версиях.
3. **Платформенная реклама:** по опубликованной официальной таблице совместимости вызовы `VKWebAppCheckNativeAds` / `VKWebAppShowNativeAds` в ОК документированы для Android. Для известных OK iOS/Web рекламные кнопки отключены, но уровни и способы получения платных за *игровые* монеты подсказок сохранены. Это консервативный режим до подтверждения реальной поддержки на этих клиентах: справочник ОК содержит устаревшие исторические разделы, поэтому в новой версии SDK возможности могут различаться.
4. **Первые 30 секунд:** ОК запрещает показ рекламы в течение первых 30 секунд после установки. Добавлена более строгая защита: в первые 30 секунд *каждого нового запуска* ОК-реклама вообще не запрашивается. В VK логика показов сохранена. Реклама вне активного геймплея и на переходах (после двух уровней, с минимум 90 сек между показами), rewarded только по инициативе игрока.
5. **Результат rewarded:** игрок видит сообщение после успешного показа и награждения; при отмене/ошибке награда не начисляется. Параметры `ad_format` оставлены официальные.
6. **Лёгкое выделение сосудов:** раньше на каждом первом/втором нажатии в выборе пары `render()` целиком удалял и заново создавал DOM бутылок и кристалла. Теперь `renderSelectionOnly()` обновляет CSS-классы, доступность маршрутов и подсказку, а полный рендер вызывается лишь при изменениях головоломки.
7. **Лёгкая анимация (по умолчанию Medium):** живой золотой свет и стеклянные эффекты остаются, но пульсация подсвеченных линий меняет прозрачность, а не пересчитывает дорогостоящий SVG-фильтр на каждом кадре. Для High сильное свечение остаётся прежним.
8. **Оптимизация декоративных частиц:** контекст Canvas переиспользуется, исключено ненужное создание массива в каждом кадре.
9. **Предпросмотр ОК:** добавлены HTML meta description, og:title, og:description. `og:image` не подставлен наугад: требуется абсолютный HTTPS-URL на реальном домене игры и настоящая иконка.
10. **Кеш:** новые версии URL изменённых JS/CSS-ресурсов `v=14.2.0`. Кампания и формат облачных/локальных сохранений остались прежними.

## Измерения производительности (только тестовый Chromium)

Метод: Python Playwright и Chromium, виртуальное окно 1280×800 либо 390×844; для условного слабого телефона `Emulation.setCPUThrottlingRate = 4`. Для каждого случая 30 выборов/отмен выделения бутылки. Измерен синхронный JavaScript обработчика (`performance.now()`), отдельно интервалы `requestAnimationFrame` после запуска. **Эмуляция CPU не равна реальной модели телефона**.

| Сценарий | R14.1, медиана нажатия | R14.2, медиана нажатия | Ускорение именно обработчика |
|---|---:|---:|---:|
| ПК 1280×800 | 4,9 мс | 0,2 мс | ~24,5× |
| Телефон 390×844 | 4,7 мс | 0,3 мс | ~15,7× |
| Условно слабый телефон 390×844 (CPU x4) | 14,8 мс | 1,8 мс | ~8,2× |

Семплирование `requestAnimationFrame` на бездействующем поле: интервалы ~16,7 мс и до, и после; в отдельной сцене с одним активированным маяком — то же. **Подтверждённого роста общего FPS с 60 до большего значения нет**, и реальная частота отображаемых кадров WebView без физических устройств неизвестна. Ценность оптимизации — меньшая нагрузка CPU и потенциально меньше микрофризов при управлении.

Фактический FPS на Android/iOS, частота 30/60/90/120, GPU frame-time, нагрев и расход батареи — не измерены.

## Проверки после исправлений

- `node --check assets/js/app.js`, `node --check assets/js/r13-visual.js` — успешно.
- `node tools/check-levels.cjs` — 180/180 сертификатов решаемости, 0 ошибок. **Это алгоритмическая проверка, не ручное прохождение всех уровней.**
- Playwright: обычный браузер, эмуляция VK Android, OK Android, OK iOS, OK desktop_web. Все 5 сценариев без JavaScript-исключений; VK init и OK client-detection прошли на имитаторе Bridge.
- Полный первый уровень пройден **реальными событиями click по бутылкам** в локальном Chromium и с имитацией OK Android. Кристалл, линии и экран победы отображались.
- OK Android: ранние вызовы rewarded/interstitial отфильтрованы; после программного продвижения тестового времени реклама доступна; награда начислена ровно один раз.
- OK iOS / OK web: не отправляются неподдерживаемые события для свайпа и нативной рекламы.
- Финальный уровень 180: поле/сосуды/линии визуально загружены на desktop и mobile. Все его ходы вручную не воспроизводились.
- Cloud Storage был ранее протестирован с подменой VK Bridge в R14.1, соответствующие функции в R14.2 не менялись.

## Перед релизом

1. На реальном HTTPS-URL протестировать загрузку всех файлов, ответ CDN SDK, кэш после обновления GitHub Pages и чтение/запись реального облака VK / ОК.
2. Проверить на физическом Android и iOS, в десктопном VK и OK, все кнопки, масштаб, навигацию, фоновые переходы, сохранение и подгрузку SDK.
3. Подтвердить, поддерживаются ли рекламные события в актуальных ОК iOS/Web. Если да — снять консервативную блокировку и проверить настоящий показ. Если нет — оставить текущий режим.
4. Обновить страницу приложения и проверить модерацию **отдельно** на обеих площадках. Для публикации в ОК включить «Опубликовать в Одноклассниках» в панели ВК, привязать ОК-разработчика; фактический интерфейс личного кабинета необходимо проверить.
5. После получения рабочего домена добавить абсолютный HTTPS `og:image`, подтвердить права на иллюстрации, добавить контакты поддержки и сведения разработчика.
6. Сверить **полный текст** https://dev.vk.com/ru/mini-apps-rules по открывающейся у владельца странице. Данный аудит не заменяет чтение недоступного оригинала.
