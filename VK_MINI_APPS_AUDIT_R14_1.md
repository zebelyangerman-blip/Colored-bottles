# «Атлас света» R14.1 — аудит VK Mini Apps

**Дата:** 12 октября 2026 года.  
**Исходная сборка:** `ATLAS_LIGHT_R14_LUMINOUS_RELEASE.zip`.  
**Статус:** техническая проверка и исправления проведены; **полное соответствие всем правилам VK / прохождение модерации не подтверждено**.

## Пределы проверки

Страница, непосредственно указанная владельцем: <https://dev.vk.com/ru/mini-apps-rules>, не была доступна для получения её актуального полного текста в ходе проверки. Поэтому документ **не выдаётся за постатейную сверку со всей редакцией правил 2026 года**. Проверены доступные официальные материалы VK/VKUI, публично отражённые разделы документации, клиентский код и тестовая работа игры. Реальные обращения к VK API воспроизводились посредством контролируемого имитатора VK Bridge, а не из действующего кабинета приложения; нельзя утверждать, что реальные рекламные показы и облачная синхронизация заработали на VK без дальнейшего теста.

## Внесённые правки

1. **SDK.** В `assets/js/app.js` VK Bridge зафиксирован на `2.15.11`. При запуске из VK сначала используется `unpkg.com`, при ошибке / тайм-ауте пробуется `cdn.jsdelivr.net`. На обычном сайте без параметров запуска VK лишний SDK не загружается. Это резервирование CDN, а **не офлайн-копия** библиотеки. Запрос `VKWebAppInit` и обработка неудачи сохранены.
2. **Возврат.** Добавлена история переходов `menu → inner → rules` с обработчиком `popstate`. Системная кнопка Android «Назад» не должна непосредственно закрывать игру, пока открыт её внутренний экран; из правил возвращает в текущую игру. Настройки `VKWebAppSetSwipeSettings({history:true/false})` переключаются при изменении экрана. Собственные кнопки продолжают работать.
3. **Rewarded-реклама.** Непосредственно перед вызовом `VKWebAppShowNativeAds({ad_format:'reward'})` снова выполняется `VKWebAppCheckNativeAds({ad_format:'reward'})`. При недоступности, отказе или отмене награда не выдаётся. Для показа предусмотрен явный клик по кнопке, текст описывает вознаграждение.
4. **Облачные сохранения.** Для `VKWebAppStorageSet` учтено задокументированное ограничение на размер значения: компактное состояние до **3500 байт** сохраняется как раньше в `color_sort_atlas_v5`; при превышении оно разбивается на части по **1800 байт** (с кодированием Base64) и хранится в двух чередующихся наборах. Ключ-манифест обновляется **последним**, чтобы сорвавшаяся запись не портила предыдущий прогресс. При чтении сверяются размер и контрольная сумма. Старые форматы сохранений v2–v4 и предыдущий компактный формат v5 не удалены.
5. **Кеширование.** URL основного скрипта обновлён до `assets/js/app.js?v=14.1.0` для сброса кеша после замены файлов на GitHub Pages и других статических хостингах.
6. **Адаптация.** Сохранён responsive viewport и `viewport-fit=cover`. Существующие настройки качества, поддержка уменьшенных анимаций и safe-area от R14 оставлены без изменения.

## Доказательные тесты

- `node --check assets/js/app.js` — успешно.
- `node tools/check-levels.cjs` — 180/180, ноль ошибок сертификатов.
- Playwright/Chromium: три разрешения, вход в магазин, переход в игру, открытие/закрытие правил, возврат из выбора уровней по `history.back()`, повторная навигация; 0 ошибок JavaScript.
- Контролируемый VK Bridge: `VKWebAppInit`, `VKWebAppSetSwipeSettings(history:true/false)`, `VKWebAppStorageGet/Set`, последовательность `VKWebAppCheckNativeAds` → `VKWebAppShowNativeAds`.
- Rewarded: успешный ответ → 1 подсказка; отмена → 0 дополнительных; недоступность → `ShowNativeAds` **не вызывается**.
- Облако: образец с 180 пройденными уровнями, тремя таблицами рекордов, расширенным списком купленных тем; 5 сегментов, 11 ключей двух слотов, максимальный размер значения 2400 байт. Сохранение и чтение после переключения A→B успешны. При сбое третьей записи второе сохранение осталось целым.

**Ограничение:** браузерные тесты работают с локально встроенными ресурсами и имитатором Bridge. Они не воспроизводят настоящий мобильный WebView VK, модерацию, сеть CDN и серверы VK Storage/Ads.

## Что сделать перед отправкой на модерацию

1. Загрузить содержимое ZIP на существующий HTTPS-хостинг или через официальную VK-публикацию. Не помещать ZIP как отдельный файл вместо разархивированной структуры.
2. В реальном приложении VK на Android, iOS, мобильном Web и ПК проверить запуск, Back/Swipe, сохранение после перезапуска на другом устройстве, доступность `vk-bridge`, rewarded/interstitial и поведение при отказе в рекламе.
3. Проверить и при необходимости указать `app_id`, URL для каждой платформы, разрешённые домены, режим доступа, категорию, контакты, службу поддержки и карточку приложения в кабинете VK; это **не секреты, которые нужно подставлять наугад в исходный JS**.
4. Подтвердить права на исходные фоновые изображения/элементы оформления и соответствие обложек тому, что отображается в игре.
5. Сверить актуальную **полную** страницу <https://dev.vk.com/ru/mini-apps-rules> в авторизованном браузере или по экспортированной копии и пройти окончательную модерационную проверку. Если условия меняются, проверить их снова перед публикацией.
